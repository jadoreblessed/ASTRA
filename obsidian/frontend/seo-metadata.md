# SEO & Metadata

## Site config

`src/lib/site.ts` (`siteConfig`) is the **single source of truth** for SEO —
name, `title`, description, origin URL, OG image, Twitter handle, theme colour. The
metadata generator, `robots.ts`, `sitemap.ts`, and the JSON-LD helper all read
from it. Values are set to the studio voice ("HELION — We give them gravity"; the
description is the identity/art-direction/web pitch). `title` is the default
`<title>` and the base of the `%s — HELION` template; `name` stays the bare brand
for OG `site_name` and JSON-LD.

`siteConfig.url` comes from `NEXT_PUBLIC_SITE_URL` (see [[environment-variables]]),
falling back to `http://localhost:3000`.

## Metadata generator

`src/utils/seo/generate-page-metadata.ts` exports two builders:

```ts
import {
  generateMetadata,
  generateViewport,
} from "@/utils/seo/generate-page-metadata";

export const metadata = generateMetadata({ title: "…", description: "…" });
export const viewport = generateViewport();
```

- `generateMetadata(props?)` → a Next.js `Metadata` object: title/description,
  OpenGraph, Twitter cards, canonical, robots. `metadataBase` is **always set** from
  `siteConfig.url`, so relative URLs (OG image, canonical) resolve to absolute —
  required by social scrapers. Title is a `{ default, template: "%s — HELION" }`
  object, so a page passing `title` gets "Page — HELION" and the home route gets the
  studio default. **Icons are deliberately not set here** — a metadata `icons` field
  overrides Next's file-convention detection, so the app dir owns them instead (see
  *Static assets*).
- `generateViewport()` → the `Viewport` export. `themeColor` lives here, **not**
  on the metadata object (Next deprecated it there). Keep it equal to the
  `--background` token: it paints the iOS status bar and the Android toolbar, and
  a colour that disagrees with the page reads as a seam across the top of the
  screen. It sat at a neutral `#010101` for a while after the palette moved to
  deep blue, and that is exactly what it looked like.

Accepted `generateMetadata` options: `title`, `description`, `url`, `ogImage`,
`twitterHandle`, `author`, `siteName`. (`keywords` and the non-standard `other`
tags were dropped — no SEO value.)

## robots.txt & sitemap.xml

Generated by the Next file conventions:
- `src/app/robots.ts` → `/robots.txt` — allows all crawlers, points at the sitemap.
- `src/app/sitemap.ts` → `/sitemap.xml` — lists public routes (home only so far;
  add an entry per route as the site grows).

## Structured data (JSON-LD)

`src/utils/seo/structured-data.ts` → `getSiteStructuredData()` builds an
`Organization` + `WebSite` JSON-LD graph. The root layout renders it once in a
`<script type="application/ld+json">`.

The `WebSite` node carries `copyrightYear` / `copyrightHolder`, both read from
`siteConfig` — and so is the footer's baseline copyright line, via
`data/mocks/home.ts`. State the year in one place: a footer that disagrees with the
structured data is the sort of thing nobody notices for two years.

## Bot detection

`src/utils/is-bot.ts` exports `isBot()` — a **server-only** async helper that
reads the `user-agent` header and returns `true` for Lighthouse, Googlebot,
PageSpeed, HeadlessChrome, GTmetrix, Pingdom, Bingbot, Yandexbot.

> [!caution]
> Calling `isBot()` (or any `headers()` reader) in a route **opts it out of
> static prerendering** — a TTFB cost for every visitor. Serving crawler-specific
> behaviour also borders on cloaking. Prefer the [[animation-system|reduced-motion]]
> path (`<ReducedMotion>`): animations only touch opacity/transform, so content
> is always in the DOM and crawlers see it regardless. Use `isBot()` sparingly.

## Icons & favicon

The mark is the hero's **twin interlocking triangles** (blue→lilac `#4977FF →
#D2BDFF`, from `views/home/sections/hero-icon.tsx`) on the `#02040d` background.
Icons flow through **Next App Router file conventions**, not the metadata `icons`
field (which would override them):

- `src/app/icon.svg` — the primary favicon (SVG, sharp at every size; all modern
  browsers). Next emits `<link rel="icon" type="image/svg+xml">`.
- `src/app/apple-icon.png` — 180×180 apple-touch-icon (`<link rel="apple-touch-icon">`).
- `src/app/favicon.ico` — legacy fallback, a real multi-size (16/32/48) **RGBA**
  ICO. It must be RGBA: Next's ICO decoder rejects RGB-encoded PNG entries with
  "The PNG is not in RGBA format" and fails the build. Built with Pillow, not `sips`
  (which cannot write ICO).

The rasters were rendered from HTML/SVG with headless Chrome (there is no image
tooling in the repo; `sips` downscales). To regenerate: render the mark at a large
size, downscale to each target, and pack the ICO with Pillow in RGBA.

## Static assets

The `public/` **root** holds PWA/SEO assets: `open-graph.png` (**1200×630**, the
branded share card — mark + wordmark + studio headline), `icon-192.png` /
`icon-512.png` (PWA + JSON-LD org logo + MS tile), `manifest.json` (name,
`start_url`, `display: standalone`, `theme_color`/`background_color` `#02040d`, the
two icons), `browserconfig.xml`. Site **content** assets (images, videos) go under
`public/assets/<section>/` — see [[folder-structure]].
